# Тестовое задание: API Планировщика личных финансов

Необходимо разработать на языке Go небольшой backend-сервис с HTTP API для учёта личных доходов и расходов и получения агрегированной статистики.

Разрабатывать frontend не требуется.

## Сценарий

Пользователь фиксирует личные финансовые операции.

Например:

* получение заработной платы;
* оплата аренды;
* платёж по кредиту;
* оплата подписки;
* покупка продуктов;
* другие доходы и расходы.

Сервис должен позволять:

1. Создавать категории финансовых операций.
2. Фиксировать доходы и расходы.
3. Получать список операций.
4. Получать статистику по доходам и расходам.

Способ организации API кандидат определяет самостоятельно.

## Функциональные требования

### Пользователь

Авторизация и аутентификация не реализуются. Принадлежность данных пользователю определяется идентификатором `user_id`, который передаётся явно (например, query-параметром или заголовком) в каждом запросе.

Отдельную сущность/таблицу пользователя создавать не требуется, `user_id` используется как формальный признак принадлежности данных.

### Категории

Пользователь должен иметь возможность создавать категории финансовых операций.

Минимально необходимо хранить название категории.

### Финансовые операции

Пользователь должен иметь возможность зафиксировать финансовую операцию.

Необходимо хранить:

* пользователя (`user_id`);
* категорию;
* тип операции: доход или расход;
* сумму;
* дату и время операции.

Состав дополнительных полей кандидат определяет самостоятельно.

Все операции выполняются в одной валюте. Поддерживать несколько валют не требуется.

### Список операций

Сервис должен предоставлять список финансовых операций пользователя.

Необходимо предусмотреть возможность фильтрации как минимум:

* по периоду;
* по типу операции.

Формат ответа кандидат определяет самостоятельно. Пример возможного формата:

```json
{
  "operations": [
    {
      "id": 101,
      "type": "expense",
      "amount": 150000,
      "category": "Продукты",
      "occurred_at": "2026-07-15T18:32:00Z"
    },
    {
      "id": 102,
      "type": "income",
      "amount": 20000000,
      "category": "Зарплата",
      "occurred_at": "2026-07-01T09:00:00Z"
    }
  ]
}
```

### Статистика

Сервис должен предоставлять агрегированную статистику по пользователю за указанный период.

Статистика должна содержать:

1. Общую сумму доходов.
2. Общую сумму расходов.
3. Разницу между доходами и расходами.
4. Сумму расходов с группировкой по категориям.

Формат ответа кандидат определяет самостоятельно. Пример возможного формата:

```json
{
  "period": {
    "from": "2026-07-01",
    "to": "2026-07-31"
  },
  "total_income": 20000000,
  "total_expense": 6500000,
  "balance": 13500000,
  "expenses_by_category": [
    { "category": "Продукты", "amount": 3200000 },
    { "category": "Аренда", "amount": 2500000 },
    { "category": "Подписки", "amount": 800000 }
  ]
}
```

## Технические требования

Необходимо использовать:

1. Go.
2. PostgreSQL.
3. Docker и Docker Compose.

## Требования к реализации

1. Использовать миграции базы данных.
2. Реализовать базовую валидацию входных данных.
3. Обрабатывать ошибки и возвращать корректные HTTP-статусы.
4. Структурировать проект таким образом, чтобы код было удобно поддерживать и расширять.
5. Агрегации должны выполняться на стороне PostgreSQL.
6. Предусмотреть необходимые связи и ограничения базы данных.

Допускается использование любых библиотек и фреймворков, если их выбор обоснован.

## Репозиторий

Результат необходимо разместить в Git-репозитории.

В репозитории должна присутствовать инструкция по запуску проекта.

README должен содержать:

1. Требования для запуска и команды для сборки, запуска и применения миграций.
2. Примеры использования API.
3. Краткое описание структуры проекта и принятых технических решений.

## Что ожидается на выходе

1. Ссылка на Git-репозиторий.
2. Рабочее приложение, запускаемое через Docker Compose.
3. Миграции базы данных.
4. README с инструкцией по запуску.

## Что не требуется

Для выполнения задания не требуется:

1. Реализовывать авторизацию и аутентификацию.
2. Разрабатывать frontend.
3. Поддерживать несколько валют.
4. Интегрироваться с банками и платёжными системами.
5. Добавлять очереди сообщений.
6. Настраивать кеширование.
7. Реализовывать регулярные платежи и сложное финансовое планирование.
8. Реализовывать пагинацию списка операций.

Основная цель задания - оценить структуру проекта, проектирование базы данных, работу с PostgreSQL, реализацию HTTP API, агрегирующих запросов и общий подход к разработке backend-сервиса.
